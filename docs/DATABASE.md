## Conventions

- **Primary keys:** `uuid DEFAULT uuidv7()` (time-ordered, PostgreSQL 18 built-in).
- **Money:** integer cents (`integer`), never floating point. Prices are **gross** (B2C); the net/tax split is persisted per line.
- **Percentages:** basis points (`1900` = 19.00 %).
- **Timestamps:** `timestamptz`; every mutable table has `created_at` / `updated_at`.
- **Enums:** PostgreSQL enum types generated from the tuples in [`packages/shared/src/enums.ts`](../packages/shared/src/enums.ts) (single source of truth for DB, Zod and UI).
- **JSONB:** typed via `$type<…>()` with Zod schemas in `packages/shared/src/schemas` (seat map geometry, ticket layouts, bank adapter config, settings).
- **Secrets at rest:** AES-256-GCM envelopes (`v1.<keyId>.<iv>.<tag>.<ciphertext>`) bound to a context string; the key ring in `APP_ENCRYPTION_KEYS` supports rotation.
- **Tokens:** admin/customer sessions, customer e-mail tokens, device API tokens and pairing codes are stored only as SHA-256 hashes.

## Integrity guarantees enforced by PostgreSQL

These hold even if application code or the Redis layer misbehaves. Each one is covered by
[`packages/db/test/schema.integration.test.ts`](../packages/db/test/schema.integration.test.ts).

| Guarantee                                   | Mechanism                                                                                                                                             |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| A seat can never be sold twice              | Partial unique index `order_items_active_seat_uq` on `seat_id` where status ∈ {PENDING, CONFIRMED} (test: 8 concurrent bookings → exactly 1 succeeds) |
| Cancelled / refunded items release the seat | Same index ignores CANCELLED / REFUNDED rows                                                                                                          |
| Standing areas are never oversold           | `UPDATE … SET allocated_count = allocated_count + n WHERE allocated_count + n <= capacity` + CHECK constraint                                         |
| Sold seats are never deleted from a plan    | `ON DELETE RESTRICT` (SQLSTATE 23001); the editor soft-removes via `removed_at`, freeing label/position for a replacement seat                        |
| Access codes are never over-redeemed        | CHECK `redemption_count <= max_redemptions` (+ conditional UPDATE)                                                                                    |
| Invoice numbers are gapless                 | Row-locked UPSERT on `number_sequences` inside the business transaction; rollback releases the number                                                 |
| Events only use EVENT seat maps             | Composite FK `(seat_map_id, seat_map_kind='EVENT')` → `seat_maps(id, kind)`                                                                           |
| Order totals are consistent                 | CHECKs: `total = subtotal − discount + fees`, `gross = net + tax`, refunded ≤ paid                                                                    |
| Fee scopes are consistent                   | PER_ORDER fees only global and with explicit tax rate; one override per global fee and event; PER_ORDER lines carry no event                          |
| One customer per e-mail                     | Unique index on `lower(email)`; an account requires `account_created_at`                                                                              |
| Invoices are immutable (GoBD)               | Trigger rejects UPDATE/DELETE; only the PDF key may be set once                                                                                       |
| Scanner deltas never miss changes           | Trigger assigns a new `sync_version` from a sequence on every ticket update                                                                           |
| One valid ticket per order item             | Partial unique index on `tickets(order_item_id) WHERE status = 'VALID'`                                                                               |
| Bank transactions imported once             | Unique `(bank_account_id, fingerprint)`; statement files unique by SHA-256                                                                            |

Connection-level guard rails (set per pool): `statement_timeout` 15 s, `lock_timeout` 5 s,
`idle_in_transaction_session_timeout` 30 s. `withTransaction()` retries serialization
failures and deadlocks with jittered backoff.

## Multi-event cart & tariffs

1. The customer selects seats / GA spots in any number of events. Seats are locked in Redis
   per event; the cart (`cart:<session>`) lists all events and holds the tariff per seat.
2. Tariffs are **not** chosen on the seating chart: each seat starts with the event's default
   ticket type and is switched to a reduced tariff individually in the cart.
3. Reductions are never verified online. `ticket_types.requires_proof_at_entry` makes the
   scanner show a YELLOW warning with `scanner_warning` at the door.
4. Checkout creates one order with `order_items` for all events in one ACID transaction.
   All items must share one currency. Limits (per order, per customer, per access code) are
   evaluated per event.

## Customer accounts

Guests buy without an account; the order is linked to the `customers` row of their e-mail.
Registering later sets a password on that same row – because this exposes all earlier orders
of the address, orders are only listed after the e-mail has been verified
(`email_verified_at`). Login links, password resets and verification use `customer_tokens`.

## Fee resolution

Fees are global defaults that can be adjusted per event:

| Row                                              | Meaning                                                                       |
| ------------------------------------------------ | ----------------------------------------------------------------------------- |
| `event_id IS NULL`, scope PER_TICKET / PER_EVENT | Global default, applies to every event                                        |
| `event_id IS NULL`, scope PER_ORDER              | Charged once per order, no matter how many events it contains                 |
| `event_id` + `overrides_fee_id`                  | Event-specific adjustment of a global fee (other value, or inactive = waived) |
| `event_id`, no override                          | Additional fee for this event only                                            |

Effective fees of an event = active global fees not overridden by the event + the event's
active overrides and additional fees. PER_EVENT fees are charged once per order and event.

## Effective seat status

Not stored as a column – derived in this order:

1. `seats.removed_at IS NOT NULL` → not part of the plan (not rendered)
2. `seats.block_reason IS NOT NULL` → **BLOCKED**
3. active `order_items` row with `CONFIRMED` → **SOLD**
4. active `order_items` row with `PENDING` → **RESERVED** (Vorkasse / payment in flight)
5. Redis key `seatLock(eventId, seatId)` exists → **LOCKED** (in a cart)
6. otherwise → **AVAILABLE**

## Configuration resolution

Global settings live in `system_settings` (validated by the `SETTINGS` registry). Events carry
nullable override columns (`max_tickets_per_order`, `cart_lock_ttl_seconds`,
`bank_transfer_cancel_after_days`, …). Effective value = event override ?? global setting.
For a multi-event Vorkasse order the strictest value of all contained events applies
(earliest due date; Vorkasse unavailable if any event is too close).
Waiting-room config: event row in `queue_configs` ?? global row.
